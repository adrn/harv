# harv-hq implementation plan

This plan implements `packages/hq/docs/spec.md`. The spec is normative; where
this plan and the spec disagree, the spec wins.

The work is split into nine phases (0 to 8). Each phase is one PR that leaves
`main` green, adds its own tests, and is usable on its own: after phase 3 a
user can run harv over a catalog serially, and each later phase adds scale or
exploration on top.

Storage follows the spec's "Storage formats" section: everything hq writes is
Parquet (via `pyarrow`); only the prior cache is harv's HDF5. The one shared
I/O module, `_parquet_io.py`, owns the conventions (units in field metadata,
provenance JSON in key-value metadata, write to `.tmp` and rename), so no
other module calls `pyarrow.parquet.write_table` directly.

## Reviewing each phase

After implementing a phase on its branch, and before you open the PR, I give
you a review guide for that branch. It is part of finishing the phase, like
updating the Status table. Each guide covers, in this order:

1. **What to read first**: the files in the order that makes them easiest to
   follow, with the one or two functions in each that carry the logic.
1. **Spec and plan changes**: every behavior change or deviation, so you can
   accept or reject it before reviewing code that depends on it.
1. **Questions to check**: the specific things most likely to be wrong
   (formats on disk, error behavior, edge cases), each with where to look.
1. **How to run it yourself**: the commands that exercise the phase end to
   end on the test fixtures, and the tests that cover each behavior.
1. **What is deliberately not done yet**, so it is not mistaken for a gap.

`packages/hq/tests/integration/` for the end-to-end run and the viewer.

Shared test fixture, `packages/hq/tests/conftest.py`: a session-scoped
`tiny_rv_run(tmp_path_factory)` that writes a 20-source survey-style table
from `harv.simulate.simulate_rv_sb1_data` (a few constant-RV sources, a few
binaries, varied `n_obs`, string IDs containing `+` and `/`), a catalog table
with two photometry columns, a `prior.py` with a narrow period range, and an
`hq.toml` with `n_samples = 20_000`, `top_k = 64`, and
`flush_n_sources = 4` (so a run writes several parts). A matching
`tiny_gaia_run` uses `simulate_gaia_epoch_astrometry` the same way harv does in
its own Gaia tests (`tests/unit/periodogram/test_periodogram_gaia.py`). Every
phase's tests build on these.

## Phase 0: harv prerequisite (PR against harv) — done

hq stores samples as columns; the mapping between a `Samples` and plain
columns belongs to harv, so hq never reassembles a `Samples` by hand.

Add to `harv.samplers.samples`:

```python
@final
@dataclass(frozen=True)
class SampleColumns:
    columns: dict[str, np.ndarray]   # every parameter, plus "ln_likelihood" / "ln_prior" when present
    units: dict[str, str]            # parameter name -> unit string ("" for dimensionless)
    nonlinear_names: tuple[str, ...]
    linear_names: tuple[str, ...]
    model_type: str
    linear_extension_names: tuple[str, ...]
    metadata: dict[str, int | float | str | bool]

Samples.to_columns() -> SampleColumns
Samples.from_columns(columns: SampleColumns) -> Samples
```

- Arrays keep the `Samples`' full shape, so batched `Samples` round-trip too.
  (An earlier draft rejected batched input, but `to_hdf5` saves batched
  `Samples` today and is rebuilt on `to_columns`, so rejecting them would have
  broken it.) hq's results writer enforces flat, 1-D samples itself. Extra
  dimensionless columns (e.g. `ln_interim_period_prior`) round-trip as
  nonlinear columns, as they do in HDF5.
- Done: `samples-to-columns` branch, commit `2d4c50b`.
- `ln_likelihood` / `ln_prior` are reserved column names; a parameter with
  either name raises.
- Refactor `to_hdf5` / `from_hdf5` onto these two, so there is one mapping
  and the HDF5 format is unchanged byte-for-byte in content.
- Spec: a new "`to_columns` / `from_columns`" subsection under harv's
  `Samples` section, and a line in the `to_hdf5` / `from_hdf5` entry saying
  they are built on it. `SampleColumns` is exported from `harv.samplers`.
- Tests (`tests/unit/test_samplers/`): round trip for rejection samples with
  logprobs and evidence metadata, MCMC samples (`num_chains`), samples with an
  extra column, and samples without logprobs; batched samples round-trip; the HDF5
  round-trip tests still pass unchanged; `jax.jit`-compatibility is not
  relevant (host-side I/O), so no jit/vmap tests.

`make_prior_cache` and the prior-cache format are unchanged.

## Phase 1: packaging, config, model file, IDs, Parquet I/O, provenance — done

Done: branch `hq-phase1`. Deviations from the text below, all recorded in the
spec: config is loaded with `Config.from_file(path)` (there is no `Run` yet),
`stable_hash` is exported at the top level and specified as big-endian UTF-8,
the private modules are `_parquet_io.py` and `_model_file.py`, hq test files
are named `test_hq_*.py` so their basenames cannot collide with harv's, and
each phase adds the dependencies it imports rather than phase 1 adding all of
them up front. The Sybil pattern `harv_hq/**/*.py` misses top-level modules
(`**/` needs a subdirectory), so hq lists `harv_hq/*.py` too; harv's own
`src/conftest.py` has the same gap (its top-level modules' doctests, e.g. in
`distributions.py` and `plot.py`, never run), to fix separately.

**Packaging.** `packages/hq/pyproject.toml`:

- dependencies: `harv`, `astropy`, `jax`, `numpy`, `pyarrow` (later phases add
  `h5py`, `arviz`, `fastapi`, `uvicorn`, `jinja2` when they first import them);
- `[project.optional-dependencies] mpi = ["mpi4py"]`;
- `[project.scripts] hq = "harv_hq.cli:main"`;
- non-Python files (`templates/`, `web/templates`, `web/static`) are included
  by hatchling by default under `src/harv_hq`; check the built wheel.

Root `pyproject.toml`: add `packages/hq/src/harv_hq/_version.py` to the ruff
excludes, add `harv_hq` coverage paths, and add `packages/hq/src` to pytest
`testpaths` with a Sybil `conftest.py` there for doctests (mirroring
`src/conftest.py`).

**`config.py`.** One frozen dataclass per TOML table (`RunConfig`,
`DataConfig`, `PrepareConfig`, `CatalogConfig`, `PriorCacheConfig`,
`RejectionConfig`, `MCMCConfig`, `ResultsConfig`, `ServeConfig`), collected in
a frozen `Config` with `config_path` and `run_dir`. A single generic validator
walks a dataclass's fields: unknown keys, missing required keys and wrong
types raise `ConfigError("[data] unknown key 'rv_er'")`. Kind-specific
`[data]` keys are validated against `run.kind`. `int` fields accept TOML
integers only; `float` fields accept integers too. Relative paths resolve
against the run directory; absolute paths are kept.

**`_model_file.py`.** `ModelFile.load(path)` imports with
`importlib.util.spec_from_file_location("hq_model_file", path)`. Exposes
`make_setup`, `select_rows` and `select_for_mcmc` (the last two optional,
`None` if absent). Missing `make_setup` raises `ConfigError`.
`ModelFile.setup(kind)` calls `make_setup` once, caches the result, and checks
the model type against `kind`.

**`ids.py`.** `stable_hash(source_id) -> int` (spec §Per-source randomness),
`source_key(seed, source_id, stage) -> jax.Array`, `prior_cache_key(seed)`.

**`_parquet_io.py`.**
`write_parquet(path, columns, *, units=None, field_metadata=None, metadata=None, row_group_size=None)` builds a `pyarrow.Table`, attaches
`unit` field metadata and the key-value metadata (JSON-encoded under `hq.*`
keys), writes `path.with_suffix(path.suffix + ".tmp")`, and renames.
`read_parquet(path, columns=None)` returns the table plus decoded units and
metadata. `read_metadata(path)` reads only the footer.

**`provenance.py`.** `sha256_file`, `current_provenance(run, *, stage)`
building the spec's provenance dict, and `check_provenance(found, expected, *, path)` raising `ProvenanceError` naming the field and the file. Versions
are compared and logged, never refused.

**`init.py` + CLI skeleton.** `init_run(run_dir, *, kind)` copies the
templates and refuses a non-empty directory. `cli.py` builds the argparse tree
for every subcommand now, with not-yet-implemented subcommands exiting with a
clear message, so later phases only fill in handlers.

**Tests.** Config: a valid example parses, and each kind of invalid config
gives an error naming the key. Every key in the spec's tables is accepted, and
a test parses the spec's TOML example verbatim, so the two stay in sync. Model
file: missing `make_setup`, wrong model type for the kind. IDs: `stable_hash`
is stable across processes (a hard-coded expected value), and keys differ
across IDs and stages. Parquet I/O: units and metadata round-trip; a failure
during the write leaves only a `.tmp` (monkeypatch the writer to raise).
Provenance: a mismatch raises with the field name. `hq init` produces a
config that loads.

## Phase 2: prepare, read_source, read_sources — done

Implemented on branch `hq-phase2` (stacked on `hq-phase1`). Deviations from
the text below, all recorded in the spec where they are public: `Run` is
introduced here with only `prepare()` (later phases add their methods), and
the CLI reports user errors in one line; `select_rows` receives the full input
table (the spec said columns were dropped first, which would hide the flag
columns cuts need); a missing source ID is a built-in cut; `prepare` raises
`ValueError` when no source survives; the shared fixtures are `rv_run` and
`gaia_run` in `packages/hq/tests/conftest.py`; and the 10^5-row timing test
uses a loose 60 s bound. The prepared data records `model_file_sha256` (the
spec originally omitted it), since `select_rows` lives in the model file; so
`make_provenance` no longer has an `include_model_file` switch, and phase 3's
stages refuse prepared data built from a different `prior.py`.

`prepare.py`:

1. Read `[data].file` with `Table.read(file, format=..., hdu=...)`, keep only
   the mapped columns, apply built-in cuts, then `select_rows`.
1. Units: take the column's unit if present, else the `*_unit` key.
1. Times: `Time(col, format=time_format, scale=time_scale).tcb.mjd`.
1. Cast IDs to `int64` or `str`.
1. `np.lexsort((time, source_id))`, then `np.unique(sorted_ids, return_index=True, return_counts=True)` for row starts and counts; no
   per-source table scan.
1. Drop sources below `min_n_obs` (a boolean row mask built from the counts),
   log the count, and recompute starts.
1. Write `data.parquet` (row groups of 65,536), `data_index.parquet`, and
   `catalog.parquet` (`source_id`, `n_obs`, `time_baseline`, left-joined with
   `[catalog]` columns cast to the data ID type; name collisions raise
   `ConfigError`), all through `_parquet_io` with the same `data_id`.
   `data_index.parquet` is written last, so an interrupted `prepare` leaves no
   usable prepared data.

`read_sources(run_dir, source_ids)`: look up row ranges in the index, read
only the row groups that cover them (`ParquetFile.read_row_groups`), slice
per source, and build `RVData` / `GaiaAstrometryData` with `Q` units from the
field metadata. `read_source` is the one-ID case. Both accept a preloaded
`PreparedData` handle (index + `ParquetFile`) so a process opens the files
once.

**Tests.** Round trip: every source's arrays match the input rows after
cuts. Time conversion matches astropy for a known TDB→TCB case. Unit handling
for columns with and without units. `select_rows` is applied. `min_n_obs`
drops. IDs with `+` and `/` work (no naming restrictions). Overwrite refusal.
String and integer IDs. A catalog join with missing rows gives nulls.
`read_sources` on a scattered set of IDs reads only the needed row groups
(count calls with a spy). A 10^5-row synthetic table prepares in roughly
linear time (loose bound).

## Phase 3: prior cache, serial rejection, result parts, resume — done

Implemented on branch `hq-phase3` (stacked on `hq-phase2`). Deviations from the
text below: `Run.run_rejection` takes `shard` and `overwrite`
for now (`workers`, `mpi` and `compact` arrive with phases 4 and 5; the CLI
rejects `--workers`/`--mpi` until then), and `Run.load_source` returns
`summary=None` until phase 5. Slicing is `PreparedData.slice_ids(shard)` (no
`slicing.py` module). `Payload` carries separate `row_units` and
`samples_units`. A shared `read_rows` helper in `_parquet_io` serves both
`PreparedData` and the results reader. The writer also flushes when the loop
is interrupted by an exception, so only a hard kill loses the buffer (spec
updated). Two planned tests changed: the "prior keys do not match the cache"
failure is simulated by a sampler that raises, because a real mismatch is now
refused earlier by provenance; and the injected-period recovery check is
left to an end-to-end test with a realistic prior cache (the 20,000-sample
test cache cannot resolve periods). Weighted percentiles drop zero-weight
samples (spec updated). A failed source is not done: every resume reruns it,
and there is no `--retry-failed` flag (spec updated). From the Copilot review of PR #61: parameter names that clash with the
samples-table bookkeeping columns are refused, a resumed run checks its
`Samples` structure against the parts already written, `--overwrite` archives
have microsecond timestamps, and `run_rejection` drops `Run`'s cached index
even when it raises. Fixed in harv along the
way: `RejectionSampler` stored `n_prior_samples` in `Samples.metadata` as a
float, where harv's spec says int.

**`make_prior_cache`.** `ModelFile.setup`, then
`harv.samplers.make_prior_cache(prior, model, n_samples, path, key=prior_cache_key(seed), batch_size=...)` into `prior_cache.h5.tmp`, write
the provenance JSON (with a fresh `prior_cache_id`) to the root attribute
`hq.provenance` with h5py, and rename.

**`summary_stats.py`.** `weighted_resample(samples, key, n)` (multinomial on
renormalized `Samples.weight`) and `summary_stats(samples, data, *, min_evidence_ess, weighted)`, returning a flat dict of scalars plus a units
dict: `well_resolved` (rejection only), `period_unimodal` on the resample,
MAP values, percentiles (weighted or not), and phase-coverage stats at the
MAP sample. It calls only harv's `Samples` methods.

**`results.py`.**

- `samples_to_table(samples, source_id, *, stage)` /
  `table_to_samples(rows, schema_metadata, source_metadata)`: built on
  `Samples.to_columns` / `from_columns`; adds `source_id`, `sample_index`,
  `chain` (MCMC, from `num_chains`), and `weight` (rejection).
- `PartWriter(results_dir, stage, shard, provenance, flush_n_sources, flush_seconds)`: buffers source rows and sample tables; `add(payload)`
  appends and flushes when a limit is hit; `close()` flushes the remainder.
  A flush concatenates the buffered sample tables, assigns
  `samples_row_start`, and writes `<stem>.samples.parquet` then
  `<stem>.sources.parquet`, each through `_parquet_io` (the second rename is
  the commit). Run-wide schema metadata (`hq.model_type`,
  `hq.linear_extension_names`, `hq.nonlinear_names`, `hq.linear_names`,
  `hq.samples_metadata_keys`) is written on every part.
- `ResultsIndex.build(results_dir, stage)`: reads the `source_id`, `status`,
  `finished`, `samples_row_start` and `n_samples` columns of every
  `*.sources.parquet` with `pyarrow.dataset` (ignoring `.tmp` and orphaned
  samples files), keeps the newest row per source, and checks each part's
  provenance against the current one. Exposes `done()` (newest row `ok`),
  `status_counts()`, and `locate(source_id) -> (samples_path, start, n)`.
- `read_source_samples(index, source_id) -> Samples`.

**`rejection.py`.** `process_rejection(source_id, data, *, sampler, prior_cache, config, seed) -> Payload`: run `sampler.run_with_samples(...)`
under `warnings.catch_warnings(record=True)`, compute the summary statistics,
and return a picklable `Payload` (sources-row dict and a samples
`pyarrow.Table`, both plain host data). Any exception becomes a `failed`
payload with the traceback. Payloads are plain host data because harv/JAX
objects do not pickle cleanly across processes.

**`Run.run_rejection` (serial only).** Load setup once, build one
`RejectionSampler`, compute `slice_ids(0, 1)` minus `ResultsIndex.done`,
`read_sources` for the remaining IDs, loop, `PartWriter.add`, `close`.

**Slicing** (`PreparedData.slice_ids(shard)`): sorts the prepared sources by
`(n_obs, source_id)` and returns `order[i::n]`.

**Tests.** The tiny run end to end through rejection, producing several
parts. Binaries recover their injected period within the posterior (loose
check). `Run.load_source` returns `Samples` equal to the in-memory result
(round trip through Parquet). A model file whose `make_setup` returns a prior
whose keys do not match the cache gives `failed` with the harv `ValueError`
text in `error`, and the run continues. Crash resume: raise in a test hook at
source N; parts written before the crash are intact, buffered sources are
missing, and a rerun processes exactly the missing ones. An orphaned
`.samples.parquet` (delete its sources file) is ignored and its sources rerun.
A failed source is rerun on the next resume. `--overwrite` moves the stage directory to
`superseded-*`. Provenance: editing `prior.py` makes `run_rejection` raise
`ProvenanceError`. Same seed gives identical samples on rerun. Population
read: `pyarrow.dataset` over the samples files returns `n_sources * top_k`
rows.

## Phase 4: execution modes (shards, pool, MPI) — done

Implemented on branch `hq-phase4`. Deviations from the text below: there is
no `_threads.py`. A worker cannot pin its own threads, because unpickling its
initializer imports `harv_hq`, which loads NumPy and JAX first, so the parent
sets the thread variables in the environment the workers are spawned with
and restores its own afterwards (spec updated). The drivers take
`(ids, data, setup, sink)`: `setup` is a picklable
`functools.partial(rejection_setup, config, cache_path)` that builds the
per-source function (each pool worker calls it once), and `sink` adds to the
`PartWriter` and counts progress. There is no `run_mpi` driver: `--mpi` takes
the slice from the rank and then runs the serial driver, or the pool driver
with `--workers` (`--mpi --workers` is allowed, for one rank per node; spec
updated). With `--overwrite`,
only rank 0 supersedes, between two barriers (spec updated). Every mode logs
progress about every 5% of its slice. The real-`mpirun` test is skipped
unless `mpi4py` and `mpirun` are both present, and could not be run locally
(Homebrew's Open MPI crashes even a one-rank job on this machine), so the MPI
path is also tested with a stand-in communicator. Found along the way, and
fixed in harv: `run_with_samples` ordered parameters by set iteration, so two
processes could write differently ordered columns, and the structure check
then refused the second one (harv spec updated). From the Copilot review of
PR #63: a rank that raises calls `comm.Abort(1)`, so its peers cannot hang at
a barrier (spec updated).

**`execution.py`** wraps a per-source function in three drivers sharing one
contract: given `(ids, data, process_fn, writer)`, process every ID and pass
every payload to `writer.add`.

- `run_serial`: a loop.
- `run_pool(workers)`: `ProcessPoolExecutor(mp_context=spawn, initializer=_init_worker)`. `_init_worker` pins threads, loads the model
  file and builds the sampler into module globals. The parent has already
  loaded the slice's data with `read_sources`; each task carries one source's
  ID and its data arrays (small), so workers never open the prepared files.
  Results come back through `as_completed` and the parent writes. Bounded
  in-flight futures (`2 * workers`) so memory stays flat for 10^6 IDs.
- `run_mpi()`: lazy `from mpi4py import MPI` (an `ImportError` naming
  `hq run --mpi`), `i, n = rank, size`, then `run_serial` on the slice with
  this rank's own `PartWriter`, then `comm.Barrier()`. Rank 0 logs a periodic
  progress line from its own count times `n`; no other communication.

Each worker and rank imports harv itself, so each prints harv's one-time
float64 warning unless `JAX_ENABLE_X64` is set in the environment. hq does
not set it (a library should not edit the environment). The cluster examples
in "Setting up a project" export `JAX_ENABLE_X64=1` instead.

`Run.run_rejection(shard, workers, mpi)` validates the mutually exclusive
options and picks a driver. Part stems are `{i:04d}-of-{n:04d}-{uuid8}`, and
logs go to `logs/<stage>-{i:04d}-of-{n:04d}.log` plus stderr.

**Tests.** The tiny run with `--shard 0/3, 1/3, 2/3` gives the same IDs and
samples as serial (same seed means the same keys). A pool with 2 workers
gives results identical to serial. Shard-count independence: run `0/4` and
`1/4`, then finish with serial `0/1`; nothing is recomputed, all sources are
done. Two concurrent processes on the same slice write distinct part names
and the newest-row rule resolves the duplicates. MPI: `mpirun -n 2 python -m harv_hq.cli run --mpi` in a subprocess, skipped unless `mpi4py` and `mpirun`
are present.

## Phase 5: compaction, summarize, and status — done

Implemented on branch `hq-phase5` (off `hq`), merged as PR #65. Deviations from the text below:
`compact(stage_dir, *, stage, expected_provenance, compact_n_sources)` works
on a stage directory, and `Run.compact(stage)` wraps it. Part writing moved
out of `PartWriter.flush` into `results.write_part`, which compaction reuses,
so compacted parts are written exactly like any other.
`ResultsIndex.build` takes `paths=` (the snapshot) and reports `n_rows`, and
`results.read_source_rows` reads a list of records' full rows, opening each
file once (used by compaction and `summarize`). The tie rule and the
`load_source` retry already existed from phase 3. `Run.status()` also counts
rejection `pending` sources (spec updated). MCMC parts are not
provenance-checked until phase 6 defines their provenance. The crash tests
inject a crash after the write step, after the verify step, and after the
third deletion. Provenance now hashes `hq.toml` per table, and each output
records only the tables it depends on, so editing `[results]`, `[serve]`, a
comment, or adding `[mcmc]` no longer invalidates earlier outputs (spec
updated; `provenance.config_hashes`, `*_TABLES`). From the Copilot review of
PR #65: compaction also removes orphaned samples files over an hour old
(`ORPHAN_AGE_S`), and directory scans (`ResultsIndex.build`, `summarize`)
start over when compaction removes a part mid-scan (spec updated). From our
own review: compaction reads each input once in snapshot order (rows sorted
by `source_id` within each output part, not across parts), so memory holds
one output part plus one row group; outputs keep the newest input's
provenance; it restarts when a concurrent compaction removes an input.
Automatic compaction checks against the provenance the run wrote with.
`status` counts prepared sources only and refuses stale results. Only
`catalog.parquet` records `[catalog]`. Catalog columns may not use
`summary.parquet` names, and the summary is sorted in 4,096-row groups. One
`results.rescanning` helper replaces three retry loops; `ResultsIndex`
collects `metadata_keys` and the newest `provenance`; `write_part_tables`
writes parts from Arrow tables; `summary_stats` owns the statistic names.
`CompactReport` is exported (spec updated).

**`compact.py`**, `compact(run, stage) -> CompactReport` (counts of input
parts, sources kept, superseded rows dropped, output parts), following the
spec's six steps:

1. Snapshot the committed parts (sources files with their samples files);
   return early if already compacted.
1. Check provenance and the run-wide `Samples` structure of every input.
1. `ResultsIndex.build` restricted to the snapshot gives the newest row per
   source; sort by `source_id`.
1. For each block of `compact_n_sources`, read the selected rows' sample
   ranges from their input files, grouped by input file so each file is
   opened once per block (`ParquetFile.read_row_groups` over the spanning
   groups, then slice), concatenate in `source_id` order, recompute
   `samples_row_start`, and write through `PartWriter`'s flush path with stem
   `c-<uuid8>-<k:04d>` and row groups of 131,072. Memory is bounded by one
   block (`compact_n_sources * top_k` sample rows).
1. Verify the new sources files hold exactly the selected
   `(source_id, finished)` pairs; on mismatch, raise before deleting
   anything.
1. Delete inputs, sources file then samples file, skipping
   `FileNotFoundError`. Log the report.

Wire compaction into the drivers from phase 4: `Run.run_rejection` /
`run_mcmc` call `compact` at the end when the invocation covered the whole
stage (slice `0/1`, or MPI after the barrier, on rank 0) unless
`compact=False` (`--no-compact`). Add `hq compact [--stage]`.
`ResultsIndex.build` gets the spec's tie rule (equal `finished`: the part stem
that sorts first), and `read_source_samples` rebuilds the index and retries
once on `FileNotFoundError`.

**Tests** (in addition to the summarize tests below). After a tiny run with
`flush_n_sources = 4`: compaction leaves `ceil(n_sources / compact_n_sources)` parts, `Run.load_source` returns identical `Samples`
before and after, and a population read of the samples dataset has exactly
one row range per source. A source with a `failed` row superseded by an `ok`
retry keeps only the `ok` row. A part committed after the snapshot (simulated
by writing one between steps 1 and 6 via a test hook) survives. Crash
injection: raising after each of steps 4, 5, and mid-6 leaves a directory on
which resume, `summarize`, and `load_source` give the same answers as a clean
compaction, and a rerun of `compact` completes it. Compacting a compacted
stage writes nothing. Automatic compaction runs for `0/1` and MPI, and not for
`--shard 1/4` or `--no-compact`.

`summarize.py`:

- `summarize(run)`: `ResultsIndex.build` for both stages, then read the
  newest sources rows (all columns) with `pyarrow.dataset`, and join onto
  `catalog.parquet` by `source_id`. Build the spec's columns: rejection
  status/error and evidence columns from the rejection rows, MCMC status
  columns, `final`, and the `period_unimodal` / phase-coverage / `map_*` /
  `<param>_p*` columns from the `final` stage's row. Pending sources get
  `rejection_status = "pending"` and nulls. Write through `_parquet_io` with
  units and provenance.
- `status(run)`: `ResultsIndex.status_counts()` per stage; the CLI prints a
  small table.

**Tests.** Column set matches the spec table. Pending, failed and ok sources
all appear. `final` switches when an MCMC result is converged. A synthetic
`Samples` with known weights gives the expected weighted percentiles.
`summarize` reads no samples and no data (monkeypatch `read_sources` and the
samples reader to raise).

## Phase 6: MCMC follow-up — done

Implemented on branch `hq-phase6` (off `hq`), merged as PR #66. Deviations from the text below:
pool workers read their sources' rejection samples themselves (each task
carries the source's data and its `ResultRecord`), so the parent holds no
samples. Chains start from `num_chains` equal-weight draws (not `top_k`),
with the second half of the source's MCMC key. `r_hat_max` /
`ess_bulk_min` skip parameters constant over every draw; all constant gives
NaN, which is `not_converged`. Only `ok` rejection results can be selected,
by the rule or the hook. MCMC parts record `MCMC_TABLES` (the rejection
tables plus `[mcmc]`), so `compact`, `summarize`, and `status` now check them
too; `run_mcmc` also checks the summary's provenance and raises
`FileNotFoundError` without one (spec updated). `Run.run_rejection` and
`run_mcmc` share one driver (`_run_stage` / `_run_slice`), and
`results.process_source` holds the per-source timing, warning capture and
failure handling both stages use. `PreparedData.slice_ids` takes `among=`.
`arviz` is now an hq dependency. numpyro prints a progress bar per source;
harv's `NumpyroSampler.run` has no switch for it yet. From our own review:
the summary gains `rejection_period_unimodal`, and the rule selects on it,
so MCMC results and re-summarizing between shards never change the
selection; a summary is current only if no rejection result finished after
it started and its `ok` sources match the stage's (part `created` is the run
start, so it cannot tell); `convergence` skips only parameters whose draws
are all equal, so NaN draws fail; `RejectionSamples` re-indexes the
rejection stage when compaction removes a part mid-stage; only `hq run`
needs `prior_cache.h5` (later stages take its ID from the rejection parts);
`[mcmc]`'s `select` and `require_unimodal` are not hashed; the rule reads
four summary columns and the hook iterates batches; `status` checks the
inputs once; serial and MPI runs reuse the parent's imported model file;
`arviz` is imported lazily; the fixture builder is a session fixture
(`rv_run_factory`), since `from conftest import` broke collection from the
repo root.

`mcmc.py`, `process_mcmc(source_id, data, *, sampler, init_samples, config, seed)`: `weighted_resample` of the rejection samples for `init_samples`, then
`sampler.run(...)` with the `[mcmc]` arguments and `return_logprobs=True`.
Compute `r_hat_max` / `ess_bulk_min` from `samples.to_arviz()` with
`arviz.rhat` / `arviz.ess`, set `mcmc_status`, and compute the summary
statistics with `weighted=False`.

`Run.run_mcmc`: requires `[mcmc]` and a `summary.parquet` whose provenance
`created` is newer than the newest rejection part (else `ProvenanceError`).
Selects IDs by the rule or `select_for_mcmc`, slices them as in phase 4,
loads the slice's data and each source's rejection samples (through
`ResultsIndex`), and writes `results/mcmc/` parts. In pool mode the parent
sends each task its data and its rejection samples as plain arrays.

**Tests.** An under-resolved binary in the tiny run is selected and gets
`converged` with a modest `num_warmup` (or `not_converged` deterministically
with `num_warmup=5`; assert the status logic, not the sampler). The MCMC
samples part carries a `chain` column consistent with `num_chains`. A stale
summary raises. `select_for_mcmc` overrides the rule. Resume as in phase 3.

## Phase 7: web viewer — done

Implemented on branch `hq-phase7`, off `hq-phase6` (it needs MCMC results to
show), merged as PR #67. Deviations from the text below: the joined table is
`summary.parquet` itself, which already holds the catalog columns
(`catalog.parquet` before `hq summarize`). The app reuses `Run.load_source`
instead of its own `ResultsIndex`es, and `SourceResult` gains `rejection_row`
/ `mcmc_row` (each stage's sources-table row, for the error and warnings;
spec updated). No `jax.jit` or startup warm-up: under `jax.vmap` alone, 64
samples on a 4,096-point grid take a few milliseconds after the first
request. Source IDs travel to the browser as strings (19-digit Gaia IDs
overflow JS numbers). Rejection samples are drawn without replacement in
proportion to weight; MCMC samples are evenly spaced. RV curves drop any
`MultiSurveyOffset` (data points are shown without offsets). For Gaia, the
residual panel shows the selected sample nearest the median period. `hq serve` uses `[serve]` host and port only (no CLI overrides). Responses are
built with `JSONResponse` (which refuses NaN) rather than FastAPI's encoder.
The CLI's `_not_implemented` stub is gone, since every subcommand now exists.
The browser check (lasso, splom selection, phase fold) is still to do by
hand. From our own review: FITS catalogs work (byte strings are decoded
and big-endian numbers made native in `prepare`, which failed before this
phase too); a stage whose curves fail (NaN periods, no shown samples) gets
`curves_error` instead of failing the page; the summary row's `source_id`
is a string; Fourier fits get no sky orbit or phase fold; the app loads
`hq.toml` and the model once and swaps whole lock-built snapshots
(`Run._fresh` gives each a new results index), detecting changes by inode
and nanosecond mtime; sources files use 4,096-row groups and
`results.read_source_row` reads one; curve values are rounded to six
significant digits; `harv_hq.create_app` and `hq serve` import the web
stack lazily; `catalog.js` attaches its selection handler before the first
request and drops a sort on a removed column; `source.js` reports a failed
request. From the Copilot review of PR #67: snapshots index every stage
when built and serve the source's summary row from their own table;
`catalog.js` drops responses older than the latest request, renders source
IDs as links (keyboard access), and leaves `source_id` out of the plot
controls; `source.js` clears the Gaia panels for a stage without curves;
the search box has an accessible name.

`web/app.py`, `create_app(run_dir)`: load config, model file setup,
`catalog.parquet` joined to `summary.parquet` as a pyarrow `Table`, the
`PreparedData` handle, and a `ResultsIndex` per stage; all reloaded when the
summary's mtime changes. FastAPI routes per the spec. `hq serve` runs uvicorn
with `[serve]` host and port.

- `/api/columns`: names, dtypes, units.
- `/api/catalog?columns=&filter=&status=`: the spec's filter syntax. Returns
  columns as JSON arrays, with non-finite values as `null`.
- `POST /api/rows`.
- `/api/source/{id}` (`payload.py`): data arrays (`read_source`), up to 256
  samples (by weight for rejection, uniform for MCMC) from
  `read_source_samples`, the model curves (`predict_at_times` for RV,
  `predict_orbit_sky` plus along-scan residuals for astrometry, `jax.vmap`
  over samples, grid from `harv.plot.get_time_grid` capped at 4096), the
  summary row, and statuses and errors. One `jax.jit` per model kind, warmed
  at startup.

Frontend, plain JS with no build step and Plotly from a CDN, following the
`phobos` `star.js` pattern:

- `catalog.js`: axis/color/log/reverse pickers, a status filter, range
  filters, a `scattergl` plot, `plotly_selected` driving the table
  (`/api/rows`), sortable headers, row links, ID search, and all state in the
  URL query string.
- `source.js`: data plus curves, a phase-fold toggle, `splom` selection
  filtering the curves, a rejection/MCMC toggle, the summary table, and the
  error/warnings panel.

**Tests.** `TestClient` against the tiny run: every route returns 200 with the
expected keys; an unknown ID returns 404; IDs with `+` and `/` round-trip
through URL encoding; the filter syntax works and rejects malformed input
with 400; the source payload's curve arrays have the expected shapes;
non-finite values serialize as `null`. A gaia-run variant covers the
astrometry payload. Manual check in a browser before merge (lasso, splom
selection, phase fold).
